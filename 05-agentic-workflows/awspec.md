## Goal

Ingest unstructured customer feedback across Slack, Zendesk, and Gong, evaluate strategic alignment against active OKRs, cross-check engineering constraints, and produce an actionable Opportunity Brief with Behavior-Driven Development (BDD) acceptance criteria to eliminate manual triage and ungrounded specs.

**Primary actor:** Agent + Human-in-the-loop

## Trigger

User tags @Juno draft in a Slack thread or an automated webhook triggers on high-priority customer escalation channels (e.g., #product-escalations).

**Memory (in or out of scope)**

- **Episodic:** In-scope: Intermediate tool execution payloads, RAG chunk retrievals, ReAct scratchpad logs, and active thread draft iterations within the current execution run.   
Lifetime: Cleared automatically at the end of the run (or after 24 hours post-task session expiry)
- **Semantic:** In-scope: User and team preference overrides (e.g., preferred PRD template formatting, default Notion target directory paths, and customized BDD rule constraints).   
Lifetime: Persists across execution runs in a key-value store with a 90-day TTL (Time-To-Live)
- **Working:** In-scope: Active Slack thread message history, raw input payload (pasted Gong transcripts, Zendesk ticket bodies, user tags), current prompt parameters, and active tool call states during live processing.
Lifetime: Temporary working memory; retained live during the current execution loop and discarded immediately upon task completion or termination.
- **External:** In-scope: Read-only access to external enterprise data sources for live context retrieval via tool APIs.
read_customer_tickets (Zendesk & Gong Index): Queries rolling 90-day support tickets and sales call transcripts to extract customer escalations, error codes, and ARR impact.
search_strategy_docs (Notion / Confluence Knowledge Base): Retrieves active Q3 product strategy one-pagers, OKR priority frameworks, and business objectives.
check_eng_constraints (GitHub / OpenAPI Architecture Specs): Queries engineering architecture documents, API rate limits, database schemas, and microservice dependency limits.
Lifetime: Persistent external sources of truth; vector embeddings updated in real-time with an SLA of < 15 minutes post-source modification. Excluded from raw LLM training data.

## Human-in-the-loop

Tier 3 Workspace Mutation Gate: When the draft preview card is generated, control passes to the PM to review and explicitly click [Push to Notion Draft] or [Create Draft Jira Issue] before any external database writes occur.   
Low Model Confidence Threshold: When the ReAct model's self-assessed confidence score drops below 70% during synthesis or reasoning.   
Consecutive Tool Errors: When Juno encounters 3 consecutive tool execution failures (e.g., unreachable ticket index or broken database connector).   
Conflicting Directives: When RAG retrieval uncovers hard contradictions between documents (e.g., an active Q3 OKR request directly conflicts with an engineering API rate limit or schema constraint)

## Success & failure

- **Done when:** 1.  Success (Task Completion): Execution halts and hands back to the user when the PM reviews the Slack preview card and explicitly clicks [Push to Notion Draft] or [Create Draft Jira Issue], successfully persisting the Opportunity Brief to the workspace.
2.  Escalation / Low Confidence: Execution halts immediately and escalates to the PM with raw retrieved context attached if the model's self-assessed confidence score drops below 70% or if retrieved strategy OKRs directly contradict engineering architecture constraints.
3.  Failure (Tool Error Limit): Execution terminates and hands back an error alert if Juno encounters 3 consecutive tool execution failures (e.g., unreachable ticket database or failed API connections).
4.  Timeout / Turn Ceiling: Execution auto-terminates if the workflow reaches the hard ceiling of 5 tool turns without reaching a final draft state or if total request processing time exceeds the 15-second timeout window.
