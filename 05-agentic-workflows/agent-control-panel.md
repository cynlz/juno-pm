# Agent Control Panel · Juno

_Module 5. Generated by `M5 - Agent Control Panel.html`. Paste over `05-agentic-workflows/agent-control-panel.md`._

## Autonomy level

Juno can draft a cited P0–P3 priority, owner recommendation, and roadmap disposition for one signal, but cannot post it to Slack, write it to the Roadmap, or notify the owning pod. Only a PM's Approve, Edit, or Reject action makes it real.

## Controls

- **Kill switch:** Condition	Threshold	What "abort" means here
Step count	steps_used >= max_steps (8) with no completed draft	Stops immediately, returns a partial result labeled incomplete, showing which of the six sources were read before it hit the cap.
Elapsed time	90 seconds wall-clock, independent of step count	Aborts even if max_steps hasn't been reached, in case a single step (e.g., a slow API read) is hanging rather than the loop running long.
Cost	$0.50 per run	Same independent check as time, catches unexpectedly large context (a bloated source) rather than a genuinely long loop.
Primary signal unreadable	read_signal fails once, with no retry left	Aborts on step 1, well before max_steps, since there's nothing to triage without it.
Blocked-verb call attempted	Any call to slack.post_message, roadmap.write_item, etc.	Aborts immediately, at whatever step it occurs. Treated as a system fault, not a normal stop, escalated to engineering rather than shown to the PM.
Retry exhausted on any single source	1 retry per source (from the turn-ceiling section)	That source is marked unreachable and the run continues, it does not abort the whole run, unless it's the primary signal (see above).
- **Rate / cost caps:** The shapes, restated as a control mechanism

research_repo.read_transcript(artifact_id) → {artifact_id, type, text, author, date, source_url}
slack.read_thread(channel, thread_id) → {thread_id, messages:[{author,text,timestamp}], last_updated}
docs.read_section(doc_id, section_id) → {doc_id, section_id, text, version, last_updated}
roadmap.read_items(filter) → {items:[{item_id,title,status,pillar,priority,target_date,last_updated}]}
crm.read_account(account_id) → {account_id, name, arr, stage, notes, last_updated}

Why each field is there, not just what it is
Every read returns a last_updated or date field, never leaves freshness to be inferred. Without this, Juno would have to guess how current a source is from context clues in the text itself, exactly the kind of inference that produces a confident-sounding wrong answer. With it, the freshness thresholds from earlier (24h for Slack and CRM, 7 days for Roadmap and Capacity Note) are a straight comparison, not a judgment call.
roadmap.read_items returns status as a closed field ("committed," "planned," etc., matching the roadmap's own vocabulary), not free text Juno paraphrases. This is what makes the pre-ship gate's exact-wording check possible, per the verification section, Juno can't accidentally say "will be fixed soon" when the returned status field literally says "planned, not committed".
Every chunk that becomes a citation carries its own source_id or doc_id. This is the structural backbone of the zero-tolerance citation rule from the pre-ship gate. Requiring citations: [{claim, source_id}] in juno.create_draft's own output means an uncited claim isn't just discouraged, it's a missing required field, something the gate check can catch mechanically rather than needing to semantically evaluate the draft's prose.
Absence is explicit, never inferred from silence. juno.check_existing_draft returns {exists: bool, ...} rather than an empty response Juno might interpret either way. juno.check_freshness returns an enum ("fresh"|"stale"|"cached"|"unreachable"), not a blank field when a source can't be reached, so "I don't know" is a real, distinguishable state rather than something the model has to notice is missing and decide how to handle.
slack.read_thread returns individual messages with author and timestamp, not a summarized blob. This is specifically what makes the corroboration check honest, Juno can see that dev_dave's message says "over 50MB" without Sarah's transcript ever stating a file size, rather than a pre-summarized version that might blur the two into false agreement.
- **Escalate-on-stuck:** Rules of Engagement — Contract 3: Fallback Protocols

Every break returns something labeled and actionable, a partial result, a named failure, or an escalation, never a blank screen and never a clean-looking draft hiding what broke.

Trigger	Fallback experience
Primary signal (Sarah's transcript) unreadable, retry exhausted	No draft. Explicit text: "Cannot triage: primary signal unavailable."
2+ sources stale, cached, or unreachable	Draft still shows, labeled "Draft only, not final," each affected source named with its age.
Two sources disagree on priority tier	No resolved tier. Draft states the conflict directly and routes to the PM for adjudication rather than guessing.
Confidence below 40%	No priority tier shown at all. Raw cited excerpts presented instead, with "insufficient basis for a confident recommendation."
Turn, time, or cost ceiling hit (8 turns / 90s / $0.50)	Partial result labeled incomplete, shows exactly which sources were read before the cutoff.
Blocked-verb call attempted, or the gate itself errors	Full halt. Nothing reaches the PM. Logged and escalated to engineering as a system fault.
PM hits the manual Stop control	Whatever completed so far, labeled "Stopped by [name] at read N of 6."

## Monitoring

**Confidence thresholds (map to actions):**

≥ 60%	Ships as a standard draft. PM still reviews it (nothing here ever auto-approves), but it's presented as routine, no warning banner, no extra flags.
40–59%	Ships labeled "Needs review," with the specific depressing factors listed in plain language (e.g., "corroboration is by file size assumption, not confirmed"). Same review queue, same PM, but they see why it's uncertain before they decide.
< 40%	This is the one refinement beyond what we'd already set. Below this line, Juno does not present a priority tier at all, no P0 chip, no owner recommendation, even hedged. Instead it shows the raw cited excerpts from each source and a line stating "insufficient basis for a confident recommendation, manual triage advised."

**Checkpoints:**

Axis	Red-zone trigger	Who gets pulled in
Risk	Priority tier = P0 and the recommended owner (Platform & Infra) has no meaningful slack, per the Capacity Note	The pod's own lead, not just the reviewing PM, before the draft is treated as a basis for reprioritizing anyone's work. Committing an already-maxed team to new emergency work is the single costliest outcome this harness could produce.
Value	The draft's revenue-impact line names an account at or above $100k ARR (Initech, at $120k, qualifies)	Whoever owns that account relationship, so a misjudged reliability call doesn't quietly become a customer-facing surprise nobody on the revenue side saw coming.
Ambiguity	The signal is corroborated by only one independent source, effectively true here even at ≥60% confidence, since dev_dave's thread supports the general failure pattern but never confirms Sarah's specific case (no stated file size)	Flagged "verify before acting" regardless of the confidence score. A single complaint carries a different risk profile than a pattern across users, and the confidence math alone doesn't capture that distinction.

**North Star (re-read every loop):**

You are Juno, triaging exactly one signal: the transcript at {artifact_id}.

1. You may only read and cite these six sources: the transcript, the
   Slack thread at {thread_id}, the Strategy One-Pager's priority
   framework, the Capacity Note's Platform & Infra section, the two
   named Roadmap items, and the Initech CRM account. Nothing else you
   know or have seen is a valid source for this draft.

2. Every claim you make must carry a source_id. If you cannot name
   the source, remove the claim. Do not soften it into vaguer
   language instead of removing it.

3. You can Read and Draft. You cannot Write to any external system,
   Send a message, Notify anyone, or Close/Merge anything. If you
   find yourself about to call a blocked action, stop and report the
   attempt instead of completing it.

4. If a source is stale, unreachable, or missing, say so explicitly
   in the draft. Do not infer its likely content from the other five
   sources or from what you already know about RocketShip.

5. If two sources disagree (for example, Strategy and Roadmap
   implying different priority tiers), do not average, pick one
   silently, or reconcile them yourself. Stop and flag the conflict
   for a human to resolve.

6. Confidence is not a formality. Below 40%, do not assign a
   priority tier at all, not even a hedged one. Show the sourced
   material and say the basis is insufficient.

7. Nothing you produce is final. A draft only becomes actionable
   once a human records Approve, Edit, or Reject. Never imply
   otherwise in the language you use.

Re-read this before every read, before every draft, and before the
final compose step. If anything you're about to output conflicts
with a rule above, the rule wins.
